# PiliPlus Web Filter v0.7.1

Chrome/Edge Manifest V3 扩展。插件导入 PiliPlus 屏蔽配置，并统一过滤 Bilibili 广告、弹幕、评论和指定 UP 主内容。

## 已实现

- 导入当前 PiliPlus 评论净化 v3 JSON。
- 导出前向兼容的 `piliplus-purify` v4 JSON。
- `mutedUsers.mid` 在本地转换为 Bilibili CRC32 `midHash`。
- 绝对屏蔽（包含）、温和屏蔽（整条相等）、传统关键词和安全正则。
- 日期、时间、人数和短打卡格式识别。
- 历史 `uidHashes` 补充规则，与 `mutedUsers` 取并集并去重。
- 未知 JSON 字段安全透传；已知字段规范化重写。
- 页面命中统计、最近命中预览和频控诊断。
- 分阶段连接诊断、可复制诊断 JSON，以及静态注入失败时的主动重新连接。
- MAIN 与隔离环境使用独立脚本资源，Chrome 156 刷新后可自动完成连接。
- 点击网页弹幕可加入温和屏蔽、绝对屏蔽，或在能够唯一定位时屏蔽发送者哈希。
- 评论作者昵称旁注入“净化”按钮，可写入共用评论屏蔽名单或标记库，并即时隐藏当前页评论。
- 视频卡片 UP 主昵称旁注入“屏蔽UP”按钮；加入名单后立即隐藏同页内容，并提供撤销。
- 在首页推荐、搜索、动态、热门/排行和视频相关推荐的 Fetch 响应中按 UP 主 UID 过滤，DOM 扫描作为兜底。
- UP 主名单使用独立的 `uploaderRules.users`，不会把“隐藏投稿”误当作评论或弹幕账号屏蔽。
- 可直接合并导入 PiliPlus 的 `blackMids.json` 纯 UID 数组，并可按同一格式导回 PiliPlus。
- 默认隐藏 Bilibili 首页左侧 `.recommended-swipe` 推广轮播，并让推荐卡片以密集网格自动回填空位。
- 首页默认采用固定 6×4 净化页：前 22 格显示视频，最后一行后两格合并为净化统计卡；上游仍收集 24 个过滤后的普通视频作为显示与补位缓冲。原生“换一换”沿用相同流程；设置中可关闭。
- 首页统计卡展示本次已屏蔽总数、广告与推广、UP 投稿、规则库数量及过滤连接状态，并提供“管理规则”和 GitHub Issues 问题反馈入口。
- 点击固定的原生“换一换”后进入短暂稳定期，只对当前可见推荐网格重新分页；固定页模式隐藏随滚动移动的浮动刷新按钮，避免连续触发推荐请求。
- 设置页可随时关闭该布局规则；弹窗会显示轮播组件是否被识别并隐藏。
- 固定页模式只扩大首页推荐请求批量并重建单页，不改写分页游标；关闭固定页时首页推荐接口恢复原样透传。DOM 层继续隐藏漏网广告、屏蔽 UP 主及 `.floor-single-card` 官方分区推广位。
- 动态接口继续移除商品推广及广告关键词命中的内容。
- 隐藏视频页侧栏与条幅广告；DOM 兜底通过持续观察处理无限滚动和 SPA 重新渲染。
- 内置广告词库可每天从本仓库自动更新，也可关闭远程词库并仅使用自定义关键词。
- 快捷操作提供撤销；同文案弹幕无法唯一定位发送者时不会猜测。
- 解析或过滤失败时放行原始响应，不阻断播放器。
- 规则存入 `chrome.storage.local`，不上传配置或弹幕内容。

## 安装

1. 解压 ZIP。
2. 打开 Chrome 的 `chrome://extensions/` 或 Edge 的 `edge://extensions/`。
3. 开启“开发者模式”。
4. 选择“加载已解压的扩展程序”，选择含有 `manifest.json` 的目录。
5. 重新加载已打开的 Bilibili 视频页面。

首次加载后请在扩展详情中确认 Bilibili 站点访问已允许。若弹窗仍显示未连接，可点击“连接诊断”；诊断会分别检查标签页、URL、站点权限、隔离脚本、MAIN world、令牌桥接、规则下发与 Fetch/XHR 钩子。“重新连接”会在当前页主动补注入脚本，成功后无需重启浏览器。

点击工具栏图标可导入/导出配置、查看当前页面统计；“管理规则”页面可直接编辑各类规则。

## 净化助手快捷操作

- 点击正在播放的普通弹幕，会弹出“温和屏蔽”“绝对屏蔽”和“屏蔽弹幕发送者”。
- 发送者操作只保存 Bilibili 分段中已有的匿名 `midHash`；若相同文本在当前时刻无法唯一对应一个发送者，该按钮会禁用。
- 评论加载后，作者昵称旁会出现“净化”按钮，可将 UID 加入评论屏蔽名单或切换标记状态。
- 新增规则后会立即写入本地 v4 配置；导出 JSON 后可与 PiliPlus 配置一并备份。
- 每次快捷操作均提供短暂的“撤销”入口。

## v4 格式约定

- 顶层 `version` 只表示整个文件格式版本。
- `danmakuAssistant.version` 表示弹幕助手子结构版本。
- 高于已知版本的文件会尽力解析已知字段并产生警告。
- `mutedUsers` 规范形状为 `{ "mid": 正整数, "name": "可选昵称" }`。
- `uidHashes` 导出为8位小写十六进制；导入兼容 `0x`、大小写和缺少前导零的值。
- `uploaderRules.users` 规范形状同样为 `{ "mid": 正整数, "name": "可选昵称" }`，子结构版本当前为1。
- 插件导出会保留安全的未知字段，但当前 PiliPlus v3 重新导出时会丢弃其不认识的扩展字段。

## 正则安全

原生 JavaScript 正则不能在同步 XHR 响应路径中被可靠强制中断。v0.1 因此采用受限策略：

- 规则最长256字符，正则只处理最长512字符的弹幕文本。
- 导入时拒绝反向引用、后行断言、嵌套重复量词等高风险结构。
- 不兼容规则保留在配置中，但不参与匹配，并显示停用原因。
- 返回后发现单次匹配明显过慢时，在当前页面自动停用该规则。

这不是完整的正则沙箱。后续版本如需兼容更复杂规则，应切换到线性时间正则引擎。

## 当前限制

- 重点支持 `/x/v2/dm/web/seg.so`、`/x/v2/dm/wbi/web/seg.so` 和历史分段 protobuf。
- 尚未适配直播 WebSocket 弹幕。
- BAS、互动弹幕、图片弹幕等特殊类型尚未单独验证。
- DOM 兜底只能按文本过滤，无法获得发送者 `midHash`。
- v0.7.1 面向 Chrome/Edge 111 及以上版本。
- 视频播放页默认启用兼容模式：暂停评论/UP 主快捷按钮与 DOM 广告兜底，保留弹幕数据过滤；可在设置页开启实验性 DOM 增强进行测试。
- UP 主数据层适配覆盖当前常见的推荐、搜索、动态、热门/排行及相关推荐接口；未识别的新页面会退回 DOM 卡片隐藏。
- 评论快捷按钮兼容传统评论 DOM 和可访问的开放 Shadow DOM；若 Bilibili 使用封闭 Shadow DOM，需针对其外层事件补充适配。
- Bilibili 页面或接口更新后可能需要更新适配器。
- 首页布局同时识别带或不带 `is-version8` 的推荐网格，以及国内版与海外版推荐容器；关闭布局开关并刷新可恢复原页面。

## 隐私

所有规则匹配均在本地完成。插件不请求头像、不查询用户资料、不调用模型，也不把屏蔽名单、弹幕或统计发送到外部服务。启用远程广告词库时，后台每天只向本项目 GitHub Raw 地址读取公开的 `config/ad-keywords.json`；关闭该选项后不会使用远程词库内容。
